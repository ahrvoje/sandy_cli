LibreOffice for
AI agents.

Give an agent a LibreOffice tool with a dedicated working folder. An unrestricted Python launcher prepares the environment; Sandy runs the document job in a Least Privileged AppContainer (LPAC).

Unrestricted launcher
Prepares scratch, initializes LibreOffice once, and writes the configuration.
→
Restricted LibreOffice
Processes the agent's documents with access to the selected runtime and data folders.

The restriction applies to the LibreOffice process. The launcher runs with your normal user permissions; any restrictions on the calling agent are managed separately.

Prepare and launch

Start with an existing sandy.exe that supports [pipes], Python 3.11 or later, and an unpacked 64-bit LibreOffice folder. That folder must contain program\soffice.bin, program\soffice.com, and the rest of the application files.

Save the Python launcher and its TOML template together. The launcher uses only Python's standard library. In PowerShell, open their folder and set these paths to your own locations:

$sandyExe = 'C:\AgentTools\sandy.exe'
$libreOfficeRoot = 'C:\AgentTools\LibreOffice'
$scratchRoot = 'C:\AgentWork\office-job'

py -3 .\libreoffice-demo.py `
    --sandy "$sandyExe" `
    --libreoffice "$libreOfficeRoot" `
    --scratch "$scratchRoot"

Choose runtime and scratch folders whose access permissions you can manage as a normal user. Keep the runtime, launcher, template, and Sandy executable outside scratch's writable profile, work, and temp folders. Use a new scratch folder for the first launch; the launcher creates it.

  1. The launcher creates the data folders and sets the LibreOffice environment.
  2. On the first launch, it initializes the profile outside LPAC using LibreOffice's normal launcher and a generated sample document. Agent documents and supplied arguments are used only in the sandboxed phase.
  3. It writes a complete TOML file, including the named-pipe mapping, and uses Sandy to start soffice.bin inside LPAC.

Writer opens work\LPAC-demo.fodt. Keep the terminal open and close Writer when finished. This completes the run and its cleanup. Replace py -3 with your Python executable if needed.

Run an agent job

Put approved input documents in <scratch>\work. Pass LibreOffice arguments after --. For example, after closing Writer, convert the sample document to PDF:

py -3 .\libreoffice-demo.py `
    --sandy "$sandyExe" `
    --libreoffice "$libreOfficeRoot" `
    --scratch "$scratchRoot" `
    -- --headless --convert-to pdf LPAC-demo.fodt

LibreOffice runs with work as its current directory, so both LPAC-demo.fodt and the resulting LPAC-demo.pdf are there. Replace the input name with the agent's document. Collect the output after the launcher exits.

Reuse scratch for sequential jobs that share a profile. Use a separate scratch folder for each independent or simultaneous job; the launcher prevents concurrent use of one profile. If you change the LibreOffice build or move the profile, use a new scratch folder.

The launcher supplies the profile location and environment. It passes the executable and application arguments through Sandy's -x switch, so they do not belong in TOML.

One place for application data

<scratch>\
  profile\
    user\                 LibreOffice settings and extension state
    home\                 HOME and USERPROFILE
    appdata\local\        LOCALAPPDATA
    appdata\roaming\      APPDATA
  work\                   approved input and output documents
  temp\<run ID>\          TEMP and TMP; removed when the run ends
  runs\<run ID>\
    libreoffice.toml      complete configuration for this run
    *.log                 launcher, LibreOffice, and Sandy logs
    result.json           completed run details
  initialized.json        records successful first initialization
  last-run.json           current or most recent run details
  .launcher.lock          prevents concurrent use of this scratch folder

The launcher directs profile, home, AppData, and temporary paths into scratch. It sets variables for its child processes without changing the calling terminal or Windows environment settings. Windows resources and Sandy's own sandbox and recovery storage remain outside scratch.

Access and cleanup

ResourceLibreOffice access
Selected LibreOffice runtimeRead and execute; no write grant.
Profile, work, and this run's temporary folderRead, write, and delete; no file execution grant.
Selected ancestor directoriesDirectory listing only, for path lookups. The launcher selects directories it can grant without elevation.
Run configurations, logs, and launcher control filesNo file-content grant.
Windows registry and COMRegistry-read and COM capabilities, needed for startup. No registry-write grant.
Network, LAN, clipboard, and child processesDisabled.

Named pipes: LibreOffice requests a pipe outside LOCAL. The launcher calculates its exact name from the Windows user and LibreOffice profile, then writes an explicit [pipes] rule. Sandy intercepts that name and substitutes a \\.\pipe\LOCAL\… name in the sandbox's private pipe namespace. The application files stay unchanged.

LPAC also permits Windows resources and resources already allowed by its baseline permissions or selected capabilities. The folder grants above describe the additional application access; they are not a claim that every object outside scratch is inaccessible.

When LibreOffice exits, Sandy removes its temporary sandbox identity, access grants, and pipe hook. The Python launcher then removes that run's temporary folder. Profile settings, working documents, configurations, and logs remain. Check last-run.json for the exit code and temp_removed; the Sandy log records sandbox cleanup.

After forced termination or power loss, temporary files can remain. Delete retained scratch data only when no process uses it and you no longer need its documents or settings.

This workflow was tested with LibreOffice 26.8.1.1 x64 for Writer and headless PDF export.

Appendix: a complete Sandy configuration

The launcher writes a ready-to-use runs\<run ID>\libreoffice.toml for each run. Below is one fully filled example for the paths used above. Its Windows user SID and run ID are illustrative; the launcher supplies your actual values and selects the available ancestor directories.

The pipe name here matches the profile URL file:///C:/AgentWork/office-job/profile. Use the configuration generated for your run. Keep the accompanying launcher environment and -env:UserInstallation argument: TOML supplies the access rules and pipe mapping, not profile initialization or environment setup.

[sandbox]
token = 'lpac'
workdir = 'C:\AgentWork\office-job\work'

[allow.deep]
execute = ['C:\AgentTools\LibreOffice']
read = [
    'C:\AgentWork\office-job\profile',
    'C:\AgentWork\office-job\work',
    'C:\AgentWork\office-job\temp\0123456789abcdef0123456789abcdef',
]
write = [
    'C:\AgentWork\office-job\profile',
    'C:\AgentWork\office-job\work',
    'C:\AgentWork\office-job\temp\0123456789abcdef0123456789abcdef',
]
delete = [
    'C:\AgentWork\office-job\profile',
    'C:\AgentWork\office-job\work',
    'C:\AgentWork\office-job\temp\0123456789abcdef0123456789abcdef',
]

[allow.this]
# List these directories only; do not grant access to their other contents.
read = [
    'C:\AgentTools',
    'C:\AgentWork',
    'C:\AgentWork\office-job',
    'C:\AgentWork\office-job\temp',
]
# Traverse the working directory; do not grant execution to its files.
execute = ['C:\AgentWork\office-job\work']

[privileges]
registry_read = true
com = true
child_processes = false
network = false
lan = false
clipboard_read = false
clipboard_write = false

[environment]
inherit = false
pass = ['HOME', 'SAL_DISABLESKIA', 'SAL_DISABLE_OPENCL']

[pipes]
'\\.\pipe\OSL_PIPE_S-1-5-21-1111111111-2222222222-3333333333-1001_SingleOfficeIPC_cd509f78ff012726973a377ccc8c28a' = '\\.\pipe\LOCAL\OSL_PIPE_S-1-5-21-1111111111-2222222222-3333333333-1001_SingleOfficeIPC_cd509f78ff012726973a377ccc8c28a'
